# Product Vision — AI Executive Coach Command Center

## North Star

Build a calm, local-first desktop command center that helps one user think clearly, manage competing projects, decide what matters, execute the next meaningful action, and review progress over time.

The AI Executive ADHD Coach is the intelligence layer across the system. It should understand structured command-center data and provide grounded guidance, not operate as an isolated chat toy or an uncontrolled autonomous agent.

## User promise

When the user opens the app, it should help answer:

1. What matters today?
2. Which project deserves attention?
3. What is the smallest realistic next action?
4. What is blocked, stale, waiting, or at risk?
5. What decision or follow-up is being avoided?
6. What should be reviewed before planning more work?
7. How is AI resource usage being spent?

## Current implementation priority

The first concrete workflow to make reliable is the local Projects + Tasks + Kanban board. This is the active priority before Today/Focus, coach intelligence, integrations, usage tracking, or unrelated redesign. The priority is an implementation sequence, not a reduction of the long-term vision.

## Product pillars

### 1. Executive clarity

Turn a large, noisy set of commitments into a visible, prioritized operating picture.

### 2. ADHD-aware execution

Use concrete next actions, low-friction capture, focus limits, realistic planning, visible blockers, and reduced context switching. Never diagnose ADHD or make clinical claims.

### 3. Project control

Provide a simple, useful project and Kanban-style system inspired by Pivotal Tracker, Linear, and Trello without attempting to clone any of them initially.

### 4. Grounded coaching

The coach should reason from real local data, explain why it recommends something, and ask for approval before changing user data.

### 5. Measurable AI operations

Track only real, attributable API requests and token/cache data. Usage views must disclose their source and limitations.

### 6. Durable privacy

Local-first by default. No credentials in the app. No silent network behavior. No cloud sync or external integration until explicitly designed and approved.

## Future capability map

- Command Center / Today
- Focus and next actions
- Goals and outcomes
- Projects and initiatives
- Kanban board
- Tasks, milestones, dependencies, and blockers
- Decisions and decision records
- Meetings and follow-up
- Notes and knowledge
- Reviews and reflection
- Learning & Development / certification
- API, token, cache, and cost analytics
- Coach context, guidance, and approval workflow
- Settings and privacy controls

These are a direction, not a promise that every module belongs in the first release.

## Core domain model direction

Keep new data additive and versioned. Likely entities are:

- Area
- Goal
- Project
- Task or story
- Milestone
- Decision
- Meeting/follow-up
- Note
- Review
- Usage event
- Coach recommendation

Do not build a large generalized database before a real workflow requires it. Existing learning data is a separate compatibility boundary and must not be migrated casually.

## Coach behavior model

The coach should eventually:

- Read structured command-center state
- Summarize what is important
- Identify stalled or overloaded work
- Suggest a small number of realistic next actions
- Explain tradeoffs and assumptions
- Draft plans or task changes for review
- Ask before mutating data
- Record enough context to make recommendations auditable
- Continue to be useful when no AI provider is available

The coach must not:

- Pretend to know facts absent from stored data
- Fabricate progress, priorities, costs, or integrations
- Make clinical claims
- Silently create, delete, reprioritize, or complete user work
- Become a mandatory chat-first interface

## Usage and token direction

The first trustworthy source is usage generated by this app itself. Each event may eventually include provider, model, timestamp, feature, project association, request status, input tokens, output tokens, cached tokens, cache-creation tokens, total tokens, estimated cost, and request ID where available.

Provider-wide dashboards require a separately approved integration and secure credential strategy. Never imply that local app events equal total provider usage.

## UX principles

- Calm before comprehensive
- One clear next action
- Progressive disclosure instead of dashboard overload
- Visible status: active, blocked, waiting, stale, done
- Fast capture, low typing burden
- Make estimates and uncertainty explicit
- Preserve user control
- Prefer useful defaults over excessive configuration
- Make every automated suggestion dismissible and reversible

## Long-term non-goals

- Medical diagnosis or treatment
- Covert surveillance or productivity scoring
- A mandatory cloud account
- An autonomous agent with unrestricted write access
- Fake integrations or simulated analytics presented as real
- A giant all-in-one feature surface with no prioritization

## Success definition

The product succeeds when it reliably helps the user move from overwhelm to a grounded next action across multiple real projects, while preserving trust, privacy, data ownership, and the ability to understand why the system made a recommendation.
